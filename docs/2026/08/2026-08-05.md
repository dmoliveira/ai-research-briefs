<h2 id="executive-summary">Executive Summary</h2>

The strongest work this week shifts agent research from model-only capability toward runtime controls. <em>Turning Interaction History into Execution State</em> is the most actionable coding-agent paper: its Ledger layer turns long interaction traces into explicit observed, modified, and attempted state, improving SWE-bench Verified pass rates while cutting cost. <em>Real-Time Detection and Repair of LLM Agent Failures</em> is the companion monitoring paper, showing that lightweight telemetry plus deterministic verification can catch and repair many failures without judging every step with another model.

Evaluation reliability also gets sharper. <em>Judging Is Not Enumerating</em> shows that models can judge candidate correctness far better than they can author complete acceptable-answer sets, which is a direct warning for LLM-written tests, rubrics, answer keys, and RL verifiers. <em>ParEvalLayer</em> asks a practical CI question: when does a partial benchmark run support a decision, and when should it abstain?

RAG and memory work is converging on procedural discipline. <em>Before Reasoning Fails</em> separates evidence retrieval from evidence reading and demonstrates a simple Read-Gate invariant. <em>MemSIF</em> and <em>TrajWiki</em> both treat memory as structured, source-grounded state rather than a flat append-only store. Systems papers are similarly operational: <em>TELLER</em> targets cross-layer LLM inference RCA, while <em>SPEAR</em> provides the week's strongest recommender/product-search signal with RecSys 2026 venue status and deployment evidence.

<article class="entry-card">
  <h3>Turning Interaction History into Execution State: A Runtime Layer for Long-Horizon Coding Agents</h3>
  <p class="entry-summary">A deterministic Ledger layer converts coding-agent trajectories into explicit execution state and uses it to inform prompts and govern redundant commands.</p>
  <div class="entry-meta-grid">
    <div class="entry-meta-item"><span class="entry-meta-label">Published / updated</span><span>2026-08-01 / 2026-08-01; arXiv ID 2608.00808</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Authors</span><span>Zehao Wang, Yisen Xu, Chenglin Li, Chao Peng, Bram Adams, Ahmed E. Hassan, Tse-Hsun Peter Chen</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Affiliations</span><span>Not listed in arXiv metadata</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Link</span><span><a class="entry-link" href="https://arxiv.org/abs/2608.00808">https://arxiv.org/abs/2608.00808</a></span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Tags</span><span>coding agents, runtime state, SWE-bench, cost reduction, execution ledgers</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Reading profile</span><span>24-36 min - Relevance 5/5 - Quality 5/5</span></div>
  </div>
  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>Ledger distills completed agent interactions into observed, modified, and attempted state, then injects compact state views into prompts and blocks or short-circuits likely redundant commands.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>Long coding-agent runs accumulate stale observations and repeated actions, forcing the model to infer current repository state from raw history.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Context</span>As coding agents operate for hundreds of steps, context windows become less useful unless history is converted into current, actionable state.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Solutions explored</span>The paper adds an inform path before model actions and a govern path before command execution, both backed by an online execution ledger rather than extra model calls.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Key results</span>On SWE-bench Verified, Ledger raises Pass@1 from 56.2% to 64.2% with GPT-5 mini and from 75.8% to 81.0% with MiniMax M2.5, while reducing total cost by roughly 29-32%; attached to OpenAI Codex, it adds 3.4 Pass@1 points at 24.4% lower cost.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Agent history should be operationalized into runtime state rather than merely appended to context.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>This is the week's read-first engineering paper because it describes a concrete layer that many agent stacks can reproduce without retraining.</p></div>
  </div>
</article>

<article class="entry-card">
  <h3>Real-Time Detection and Repair of LLM Agent Failures</h3>
  <p class="entry-summary">A lightweight telemetry and deterministic-verification approach for detecting, rolling back, and repairing failed agent episodes in real time.</p>
  <div class="entry-meta-grid">
    <div class="entry-meta-item"><span class="entry-meta-label">Published / updated</span><span>2026-08-03 / 2026-08-03; arXiv ID 2608.02464</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Authors</span><span>Sunny Dubey</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Affiliations</span><span>Not listed in arXiv metadata</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Link</span><span><a class="entry-link" href="https://arxiv.org/abs/2608.02464">https://arxiv.org/abs/2608.02464</a></span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Tags</span><span>agent monitoring, failure repair, telemetry, deterministic verification, rollback</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Reading profile</span><span>28-40 min - Relevance 5/5 - Quality 5/5</span></div>
  </div>
  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>The paper trains microsecond-scale monitors on healthy runs and pairs them with deterministic checks that verify tool totals and required-call coverage, then rolls back and reruns flagged episodes.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>Agents can loop, drift, absorb corrupted context, or fabricate results mid-episode, while judge-model supervision is often too expensive to apply every step.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Context</span>Production agent systems need cheap failure detectors that work during execution, not only post-hoc benchmark scoring.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Solutions explored</span>The work combines one-class telemetry monitoring, CUSUM alarms, deterministic verification, and live rollback-and-retry repair.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Key results</span>On 2,823 committed episodes, the monitor reaches AUROC 0.872; deterministic coverage verification catches up to 96% of failures at zero false positives in the reported setting; repair lifts task success from 52% to 73% for about one extra model call.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Agent supervision can be split into cheap statistical alarms and exact invariants, reducing reliance on always-on judge models.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>The deterministic-verification layer is the most reusable part: product teams should encode task invariants before reaching for another judge model.</p></div>
  </div>
</article>

<article class="entry-card">
  <h3>Judging Is Not Enumerating: Silent Omissions in LLM-Authored Acceptable Sets</h3>
  <p class="entry-summary">A detailed study showing that language models can judge candidate correctness much better than they can author complete acceptable-answer sets.</p>
  <div class="entry-meta-grid">
    <div class="entry-meta-item"><span class="entry-meta-label">Published / updated</span><span>2026-08-02 / 2026-08-02; arXiv ID 2608.01000</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Authors</span><span>Wenhui Chen, Jianlin Chen, Ziyao Lin, Peiji Long, Chi Man Vong</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Affiliations</span><span>Not listed in arXiv metadata</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Link</span><span><a class="entry-link" href="https://arxiv.org/abs/2608.01000">https://arxiv.org/abs/2608.01000</a></span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Tags</span><span>LLM judges, verifier authoring, acceptable answers, RLVR, test generation</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Reading profile</span><span>45-65 min - Relevance 5/5 - Quality 5/5</span></div>
  </div>
  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>The paper compares model ability to judge whether candidates belong in acceptable sets with its ability to author those sets, finding large omission-heavy gaps.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>LLM-authored answer keys, rubrics, tests, and reward functions can silently omit valid cases that reviewers never see.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Context</span>LLMs are increasingly promoted from being evaluated to writing the evaluators used for other systems.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Solutions explored</span>The authors test finite truth sets, executable references, incomplete lexical references, verifier gates, and repair procedures based on reference execution.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Key results</span>Models judging candidates achieve much higher F1 than models authoring the full sets; on code tasks, authored suites admit only 19-42% of oracle-correct solutions despite judge F1 around 0.74-0.90; verifier gating reduces false rejection but keeps only a minority of suites.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Evaluator authoring is not equivalent to evaluator judging, and omissions are harder to audit than over-inclusions.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>This is a high-impact reliability paper because it targets a quiet failure mode in synthetic eval generation and RL verifier pipelines.</p></div>
  </div>
</article>

  <h3>ParEvalLayer: When Partial LLM-Agent Evaluations Support a Decision</h3>
  <p class="entry-summary">A decision layer for deciding when partial benchmark outcomes are sufficient, insufficient, or should abstain in agent comparisons.</p>
  <div class="entry-meta-grid">
    <div class="entry-meta-item"><span class="entry-meta-label">Published / updated</span><span>2026-08-03 / 2026-08-03; arXiv ID 2608.02444</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Authors</span><span>Wei-Jung Huang, Bonan Shen</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Affiliations</span><span>Not listed in arXiv metadata</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Link</span><span><a class="entry-link" href="https://arxiv.org/abs/2608.02444">https://arxiv.org/abs/2608.02444</a></span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Tags</span><span>agent evaluation, partial benchmarks, statistical decisions, AIMLSystems 2026</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Reading profile</span><span>16-24 min - Relevance 5/5 - Quality 4/5</span></div>
  </div>
  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>ParEvalLayer replays completed benchmark data as partial runs and labels whether the observed subset supports a predeclared comparison, requires more evidence, or should abstain.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>Partial benchmark scores are tempting for faster iteration but can be biased by task ordering, easy-case overrepresentation, or unresolved comparisons.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Context</span>Agent evaluations are expensive, so teams often want early stopping without losing decision quality.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Solutions explored</span>The layer reads paired outcomes for two systems and applies a comparison policy chosen in advance, separating decision, no-decision, and abstention states.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Key results</span>The paper shows that partial evaluations can support some decisions, but only when coverage and comparison policy are explicit rather than inferred from an early score.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Early benchmark stopping should output a decision state, not just a provisional leaderboard number.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>Useful for CI-style agent evaluation: a good partial run should tell you what decision it supports and what it cannot yet prove.</p></div>
  </div>
</article>

  <h3>Before Reasoning Fails: Pre-Evidence Procedural Failures in Agentic RAG</h3>
  <p class="entry-summary">A trajectory-level study of RAG agents that retrieve evidence but finalize before reading it, plus a minimal Read-Gate runtime invariant.</p>
  <div class="entry-meta-grid">
    <div class="entry-meta-item"><span class="entry-meta-label">Published / updated</span><span>2026-08-03 / 2026-08-03; arXiv ID 2608.02011</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Authors</span><span>Daeyoung Roh, Donghee Han</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Affiliations</span><span>Not listed in arXiv metadata</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Link</span><span><a class="entry-link" href="https://arxiv.org/abs/2608.02011">https://arxiv.org/abs/2608.02011</a></span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Tags</span><span>agentic RAG, evidence inspection, runtime invariants, retrieval evaluation</span></div>
    <div class="entry-meta-item"><span class="entry-meta-label">Reading profile</span><span>26-38 min - Relevance 5/5 - Quality 5/5</span></div>
  </div>
  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>The authors decompose RAG failures into pre-evidence discipline failures and post-gold-read failures using saved tool traces, retrieved snippets, read passages, and answers.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>RAG agents can fail before reasoning starts by skipping evidence inspection after retrieval.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Context</span>Many RAG evaluations score only final answers, hiding whether the system actually read the evidence it retrieved.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Solutions explored</span>The paper introduces a Read-Gate invariant requiring an agent to read after search and before finalization, then evaluates it on multihop QA trajectories.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Key results</span>Across 12,000 paired trajectories, failure types are largely non-redundant; forced reading improves LLM-Acc by 14.9-19.9 points on skip-reading trajectories and 3.2-9.4 points on full minimal-reasoning cells.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Evidence gathering should be evaluated and enforced as a control-flow property, not only inferred from answer quality.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>Read-Gate is simple enough to implement in real RAG agents and likely catches failures that prompt tweaks will miss.</p></div>
  </div>
</article>

  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>MemSIF organizes raw interactions into topical segments and event trajectories, then maintains CoreFact and ActiveFact memory tracks for stable and query-promoted facts.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>Temporal proximity does not always match topical relatedness, and write-time salience does not reliably predict future memory utility.</p></div>

    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Memory quality depends on both how interactions are structured and when facts are consolidated.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>The dual-track pattern is useful: not every remembered detail should become a durable user fact at write time.</p></div>

  <p class="entry-summary">An ASE 2026 paper that combines traces and logs to diagnose failures across inference engines, backends, CUDA APIs, kernels, and distributed communication.</p>
