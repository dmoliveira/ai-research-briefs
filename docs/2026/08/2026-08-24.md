<h2 id="executive-summary">Executive Summary</h2>

This week's strongest papers are about the infrastructure around agents. <em>AI4AI-Bench</em> gives recursive self-improvement a harder target by asking agents to rewrite training algorithms inside frozen repositories rather than collect more data or tune shallow hyperparameters. The best systems still close less than a fifth of the gap from shipped algorithm to task optimum, which is a useful reality check on autonomous research claims. <em>Phantom Gains</em> reinforces the same point from the measurement side: per-problem self-improvement ledgers can produce apparent capability transitions unless every statistic has a measured null.

Policy and tool control are becoming more procedural. <em>PolicyGuide</em> compiles customer-service policies into workflow graphs and guides agents at user-turn boundaries, improving tau2-bench pass rates while reducing adversarial success. <em>Outcome Monitors</em> focuses on silent tool failures, preserving suspicious outputs and giving agents recovery affordances instead of only blocking or logging.

Agent learning is also getting more concrete. <em>MidTool</em> argues that general tool use deserves mid-training data, not only post-training. <em>Break It Down, Pass It On</em> shows that subtask-level text skills transfer better than task-level or code skills. <em>Optimal Skill Selection</em> gives skill selection a submodular optimization formulation with a provable guarantee, and <em>Inducing Task Models from Computer-Use Traces</em> turns messy screenshots and input events into reusable task models that improve held-out task accuracy.

The product-systems signal is practical. <em>Pandora's AI Model Routing Box</em> treats costly model self-assessment as an optimal search problem. <em>Adaptive Compression for Edge-based RAG</em> makes context compression a runtime control problem tied to device telemetry. In recommendation, <em>Do Sequential Recommendation Benchmarks Really Require Higher-Order Sequence Modelling?</em> is the standout because it challenges whether common benchmarks measure what transformer recommenders claim to improve.

<h2 id="key-trends">Key Trends</h2>

<div class="brief-trend-grid">
  <div class="brief-trend-card"><p><strong>Self-improvement claims are meeting stronger controls.</strong></p><p>AI4AI-Bench and Phantom Gains both show that apparent improvement can evaporate unless tasks isolate algorithmic change and audits include measured nulls.</p></div>
  <div class="brief-trend-card"><p><strong>Policy compliance is becoming workflow-level.</strong></p><p>PolicyGuide moves beyond action-local guards by representing policy as persisted graph state with step-specific remediation.</p></div>
  <div class="brief-trend-card"><p><strong>Agent memory is shifting from recall to current-state tracking.</strong></p><p>StateMemBench evaluates whether agents answer from superseded or current facts, a sharper fit for long-running product agents.</p></div>
  <div class="brief-trend-card"><p><strong>Routing and inference are becoming economic decisions.</strong></p><p>Model routing, adaptive RAG compression, and adaptive reasoning all trade quality against token, latency, energy, or evaluator cost.</p></div>
  <div class="brief-trend-card"><p><strong>Skills are now an optimization surface.</strong></p><p>MidTool, cross-task skill transfer, and bicriteria skill selection all treat skill content, selection, and training exposure as first-class system design choices.</p></div>
  <div class="brief-trend-card"><p><strong>Recommender benchmarks need harder baselines.</strong></p><p>Simple recency-weighted probes beat or rival complex sequence recommenders on several standard datasets, raising the bar for claimed sequence-model gains.</p></div>
</div>

  </div>
  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>Outcome Monitors detect contract violations in tool results, preserve the suspect result, and return a nonbinding receipt naming the violated property plus recovery tools.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>Agents can recover from explicit tool errors, but silently malformed or semantically impossible outputs may be consumed as facts.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Context</span>Production tool use often fails through stale cache pages, impossible prices, malformed business states, or successful HTTP responses with wrong content.</p></div>

    <div class="entry-section"><p><span class="entry-section-title">Conclusion</span>Silent tool failures need recoverable outcome-level instrumentation, not only exception handling.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">My take</span>The useful detail is that recovery-tool lists, not diagnostic verbosity, drive the gain; that is a concrete design lesson for agent runtime receipts.</p></div>

  <div class="entry-section-grid">
    <div class="entry-section"><p><span class="entry-section-title">Summary</span>The paper audits three rounds of rank-32 LoRA self-training on Qwen3-8B against a frozen control that goes through the same pipeline.</p></div>
    <div class="entry-section"><p><span class="entry-section-title">Problem investigated</span>Per-problem gain/loss ledgers difference noisy estimates and can interpret batching artifacts or decoding variance as capability changes.</p></div>
